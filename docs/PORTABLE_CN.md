# MacKMLink 修复助手：双击使用

## 三步开始

1. 连接 USB 对传硬件，让原厂安装程序完成安装。
2. 解压整个 ZIP，双击 `MacKMLinkRepair.exe`，无需安装 Python 或输入命令。
3. 检查自动找到的原程序路径，点击“一键修复并启用”，等待状态显示修复版正在运行。

程序会生成修复副本、自动验证、切换运行实例，并将原有 `CS Dispatch`
登录启动项指向修复版。切换时连接可能短暂中断，请在方便时操作。
之后可关闭修复助手；MacKMLink 会独立运行，登录启动也不依赖助手。

## 按钮

- **一键修复并启用**：检查版本、生成和验证独立副本，启动修复版并配置登录启动。
- **启动修复版**：使用已经准备好的副本，并重新配置登录启动；无需再次修补。
- **恢复原版**：切换回原厂安装的程序，并让登录启动指向原厂程序。
- **检查状态**：检查原件、运行路径、修复副本和登录启动配置。
- **打开修复目录**：查看本机生成的备份、清单、验证记录和运行依赖。

没有自动找到时，点击“选择文件…”，选择原厂安装后的
`FunctModules\{模块编号}\MacKMLink.exe`，通常位于
`%APPDATA%\OTi\MacKMLink1325\FunctModules\…`。
不要选择 ZIP 内的助手、修补后的 EXE 或 USB 虚拟光驱中的安装器。

## 修复文件存放位置

默认位置是 `%LOCALAPPDATA%\Open-MacKMLink\Repairs\<安装标识>`。
如果已在其他项目目录运行了可验证的修复版，助手会复用该项目，
例如本机的 `E:\Projects\Applications\MacKMLink-Repair`。
成功启用或恢复时会记住该目录，后续仍能重新找到修复副本。

原安装 EXE 不会覆盖。`artifacts` 内含原件备份与修补清单，
`runtime` 内含独立修复版及运行依赖。
启用修复版后，请保留修复目录；登录启动直接使用其中的 EXE。
助手本身和解压目录可以移动，关闭助手不会退出 MacKMLink。

## USB 硬件、换电脑和重装

本机硬件带 USB 虚拟光驱，`autorun.inf` 指向原厂 `SKLoader.exe`。
硬件中的安装文件保持原厂状态。换电脑或重装时先让硬件完成安装，
再运行助手；无需从旧电脑复制厂商程序。

登录启动与 USB 加载器是两个入口。重新插拔、原厂重装或更新后，
原版可能再次启动或改写登录启动项；点击“检查状态”，必要时点击
“启动修复版”或“一键修复并启用”。助手没有改写硬件内的安装介质，
也没有常驻拦截 USB 加载器。实际插拔及下一次 Windows 登录尚未验证。

如果 Windows 已禁用 `CS Dispatch`，助手会提示且保留该状态；请在
“设置 → 应用 → 启动”启用它后重试。
失败详情自动保存于 `%LOCALAPPDATA%\Open-MacKMLink\Logs`，界面显示具体位置。

## 支持范围和恢复

便携助手要求 Windows 10/11 x64，以及通常随系统提供的 .NET Framework 4.x。
目标 MacKMLink 是 x86 程序。当前仅支持原件版本 `1.0.1066.111`，
并进一步核对 SHA-256；版本号相同但内容不同也会拒绝修补。
这是原厂程序的隔离补丁，界面为简体中文，不是完整重写的 MacKMLink。

原件 SHA-256：
`cb06f731cc31c3d199a54ca9341645347e2386bfb859b3f92fbf16f891a23c09`

修复副本与助手没有厂商签名；原件签名和 Windows 安全设置保持不变。
原件、修复副本或运行记录变化时会拒绝操作；请保留日志供排查。
已验证空指针防护的 30,000 次原生分支；用户一次真实截图没有断连或卡顿，
且可以在 Windows 粘贴。偶发故障的长期稳定性与 Mac 图片传输仍待验证。

需要回退时点击“恢复原版”。确认原版正在运行且登录启动指向原版后，
才可以删除修复目录；原厂安装及硬件仍保留。
